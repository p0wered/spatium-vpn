# SpatiumVPN — проектный документ

> Pet-проект для портфолио. Лендинг + dashboard вымышленного VPN-сервиса.
> Главный акцент — **дизайн**: тёмная премиум-тема, эстетика Apple последних лет (Liquid Glass).
> Реального VPN не существует, все данные и функции — mock.

---

## 1. Концепция и смысловая часть

### Позиционирование

SpatiumVPN — сервис с тремя смысловыми столпами (на них опирается весь текст сайта):

1. **Обход блокировок** — основной сценарий: доступ к заблокированным государством сервисам. Современные протоколы, устойчивые к DPI.
2. **Приватность** — анонимное использование интернета, no-logs, шифрование.
3. **Гейминг** — выделенные игровые сервера: низкий пинг, минимальные потери пакетов, без троттлинга.

### Модель работы (важно для dashboard)

На сайте/в дашборде **нет кнопки Connect и функционала подключения**. Модель как у панелей Marzban/Remnawave: пользователь покупает подписку → получает ссылку-подписку / QR-код / конфиги → подключается через клиент. Рекомендуемый путь — **собственное приложение SpatiumVPN** (deep-link «add subscription in one tap»); **сторонние клиенты** (v2RayTun, Happ, Streisand, Hiddify и т.п.) поддерживаются как альтернатива. Dashboard — это личный кабинет: статистика, подписка, сервера, настройки.

Реального приложения не существует: его UI делаем как страницу в браузере под размер телефона — чисто для скринов в рамку `iphone-17-mock.png`.

**Биллинг-модель:** баланс-кошелёк + ежедневные списания. Баланс определяет, на сколько хватит подписки («до какого числа» — производная от баланса и тарифа). Пополнение — фиктивное: страницы оплаты нет, но UI (кнопка Top up, история транзакций) закладывается с расчётом на неё.

### Языки

Английский + русский (i18n). Основной для портфолио — английский.

## 2. Дизайн-система

### Позиция визуала (05.08.2026)

SpatiumVPN живёт **между двумя полюсами**: сдержанными продуктовыми лендингами (Linear, Vercel, Resend — графика почти отсутствует, её роль играет UI собственного продукта) и работами с Awwwards (вау есть, но сайт ощущается непропускаемой рекламой, а не сайтом). Целимся в середину: страницу можно спокойно читать, но в ней есть один-два момента, ради которых её показывают друзьям.

Практические следствия:

- **Вау берём объяснением продукта, а не аттракционом.** Эффектная секция обязана делать понятнее то, что словами объясняется хуже (как именно трафик проходит DPI). Эффект, не несущий смысла, — вырезаем.
- **Цену Awwwards не платим:** нет прелоадера с процентами, кастомного курсора, звука, scroll-jacking (см. п. «Анимации и движение»), обязательной анимации входа у каждого блока. Всё это читается как «сайт важнее того, что на сайте».
- **Продуктовый UI не заменяет графику, но и не исключается**: у нас есть готовый dashboard, и живой кусок продукта (список серверов с пингами) сильнее любой нарисованной иллюстрации — там, где он уместен.

Правила:

- **«Цвет живёт в свете»** (главный принцип цвета, принят 31.07.2026). Отдельного акцентного цвета нет — токен `--color-accent` удалён. Цвет появляется **только как свет**: белое ядро с холодным спадом. Два световых токена: `--color-ice` #b4d2ff (светлый ледяной — спад glow, градиенты ключевых цифр, заливка графика) и `--color-beam` #426eff (глубокий синий — только в глубине световых полотен и selection, никогда на элементах). Палитра совпадает со Strands в Hero (#b4d2ff / #426eff / #ffffff) — свет по всему сайту один и тот же. Поверхности, текст, бейджи, статусы — монохром; цветных элементов UI не существует.
- Радугу/спектр в UI не тащим. Допустимы едва заметные спектральные блики как «физика стекла»: реализована «дисперсия на грани» — spotlight рамки GlassCard расщепляется на два смещённых холодных радиала (ледяной/холодно-фиолетовый). Только холодные оттенки.
- Тёплых цветов нет нигде.
- Карточки всегда заметно светлее фона — иначе не читаются стекло и бордеры.
- **Кнопки — белые**: primary CTA — белая заливка, glow — белое ядро с ледяным спадом (`shadow-ice`). При hover primary зажигается тем же светом, что ореол GlassCard: утилита `.btn-glow` — тот же `--halo-color` и тот же стек теней с квадратичным спадом, `plus-lighter`, но по всему периметру, без привязки к курсору (разгорается .16s, гаснет .5s). Только у primary: secondary и ghost света не несут — иначе теряется иерархия CTA.

### GlassCard — базовый компонент карточки

Единый переиспользуемый компонент для всех карточек/блоков (bento, pricing, dashboard-виджеты):

1. **Градиентный бордер «свет сверху»** — не solid: псевдоэлемент с `padding: 1px` + `mask-composite`, фон `linear-gradient` сверху вниз (белый 14% → 8% → 5%, значения откалиброваны). Имитация света, падающего сверху.
2. **Hover-подсветка от курсора (spotlight)** — CSS-переменные `--x/--y` обновляются от позиции мыши, два слоя:
   - `radial-gradient` подсветка фона карточки вокруг курсора;
   - усиление градиентного бордера рядом с курсором.
     База — SpotlightCard из React Bits, дорабатываем исходник.
3. Скругления крупные (Apple-like, ориентир 20–28px), фон `--surface-1`.
4. **Внешний ореол** (проп `halo`, опционально) — по мотивам React Bits BorderGlow: многослойный box-shadow, обрезанный conic-маской по углу курсора, `plus-lighter`. Взят только сам ореол: mesh-градиенты оригинала отброшены (нарушают правило одного акцента), state-трекинг заменён на CSS-переменные без ре-рендеров. Цвет холодно-белый (`--halo-color`). Ореол проявляется только при hover (по близости курсора к кромке), поэтому допустим на всех bento-карточках. Авто-sweep (свет пробегает по контуру при появлении) — зарезервирован строго под Pricing, в других секциях не используем.
   **Важно:** ореол рисуется наружу (обёртка с `inset: -40px`), поэтому `overflow-hidden` вешать на саму карточку с `halo` нельзя — от свечения останется только внутренняя (inset) часть. Если контент нужно обрезать по кромке (как макет телефона в Setup), `overflow-hidden rounded-[inherit]` ставится на внутренний контейнер-обёртку контента.

### Grain

Едва заметный шум на фоне (Hero, возможно другие крупные секции — не глобально):

- инлайновый SVG `feTurbulence` или тайл-PNG, `opacity: 0.03–0.05`;
- **статичный**, не анимированный (GPU + не отвлекает).

**Правило кромок:** любой слой, меняющий яркость фона (grain, WebGL-канвас, свечение), не должен обрываться на границе секции — на чистом `#000` заметен даже перепад в 2%. Кромки гасим градиентной `mask-image` (см. Hero). Проверка — замер яркости строк пикселей на стыке (скрипт `seam-check.mjs` в scratchpad).

### Типографика

- **Geist** — основной (кириллица поддерживается с v1.3).
- **Geist Mono** — технические элементы: список серверов, IP, пинг, трафик, конфиги.
- Подключение через CSS-переменные (`--font-sans`, `--font-mono`) — замена шрифта бесплатна.
- Альтернативы на случай замены: Inter, Manrope, Onest, Golos Text (у двух последних лучшая кириллица); моно — JetBrains Mono.
- Bento-карточки: крупный заголовок + **короткое описание в 1–2 строки** цветом `--color-fg-muted`. Больше текста, чем у Apple (у них часто только заголовок), но описания держим максимально сжатыми — «воздух» важнее полноты.
- ~~**Оптический отступ у скруглений** (`pl-2` тексту над скруглёнными блоками)~~ — **отменено 31.07.2026**: на практике отступ сбивал выравнивание по левому краю и читался как случайный сдвиг, а не как оптическая компенсация. Текст выравниваем по краю контейнера без доп. `padding-left`.

### Анимации и движение

- **Framer Motion** — reveal-анимации при скролле (`whileInView`), микровзаимодействия, переходы.
- **Fullscreen-композиция.** Hero — строго `100vh`. Допустим мягкий `scroll-snap: proximity` на ключевых секциях, mandatory — запрещён.
- ~~**НЕ scroll-jacking, обычный нативный скролл.**~~ — **пересмотрено 05.08.2026**: на лендинге включена инерция скролла (**Locomotive Scroll v5**, `src/lib/smoothScroll.ts`). Изначальный запрет был про подмену скролла своим — именно так работает Locomotive v4: он оборачивает страницу в transform-контейнер, что сломало бы `fixed`-хедер с GradualBlur, позиционирование WebGL-слоя в Hero и весь `whileInView` (IntersectionObserver считает вьюпорт по нетронутому нативному скроллу). v5 построен на Lenis и вместо подмены анимирует нативный `scrollTop` — скроллбар, `position: fixed`, якоря и IntersectionObserver работают как есть. Поэтому запрет снят: цена, ради которой он вводился, не платится.
  - **Скоуп — только лендинг.** Инстанс монтируется хуком `useSmoothScroll()` в `LandingPage` и уничтожается при уходе со страницы. В dashboard и `/app` скролл утилитарный: инерция в списках и таблицах только мешает.
  - **Калибровка** — `lerp: 0.1` (≈ 0.54 с до 95% пути на один шаг колеса): сдержанно, читается как отполированность, а не как эффект. Единственная ручка силы инерции, крутится в `smoothScroll.ts`.
  - **Тач не трогаем** (`syncTouch: false`): у нативного скролла мобильных своя привычная физика, подменять её вредно.
  - `prefers-reduced-motion` — инстанс не создаётся вовсе (и уничтожается на лету при смене системной настройки), скролл остаётся нативным.
  - Переходы по якорям (`lib/scroll.ts`) идут через инстанс: нативный `scrollIntoView` дерётся с Lenis за позицию. Замок скролла у overlay-меню — `setScrollLocked()`: одного `overflow: hidden` на body мало, инстанс нужно останавливать явно.
  - Побочно доступен parallax через `data-scroll-speed` на элементах — пока не используется, секций лендинга ещё нет.
- Возможна одна sticky-секция со scroll-linked анимацией как «вау-момент» (решим на реализации).
- **`prefers-reduced-motion` обязателен**: отключение/упрощение анимаций + статичный fallback вместо WebGL-фона.
- **Pill-переключатели** — единый компонент `PillTabs` (`src/components/PillTabs.tsx`): подложка активной опции (`bg-white/12`) переезжает между кнопками через `layoutId` (motion), spring 450/38; при reduced-motion — мгновенно. Используется во всех сегментированных контролах dashboard (период графика, тип сервера, платформа, язык).

### Контраст контента над WebGL-фоном

Текст всегда остаётся белым (чёрный отпадает: фон анимирован и реагирует на мышь — яркость под текстом непостоянна, плюс ломается консистентность с тёмным сайтом). Приоритет решений:

1. **Композиция** (выбранное решение для Hero): текст не кладётся на яркое ядро — световое полотно опущено ниже заголовка и идёт **поверх контента** (слой `z-20` + обязательный `pointer-events-none`, иначе перехватывает клики/выделение); сабтайтл и CTA — под полотном. Grain — верхним слоем (`z-30`), ложится и на свет.
2. **Text-shadow** — мягкие тени на заголовке/сабтайтле (`0 2px 32px rgb(0 0 0/.55)`), страхуют на ярких пятнах, на тёмных участках невидимы.
3. **Scrim** (запасной приём, в Hero не используется — пользователю не понравился): радиальное затемнение за контентной зоной между фоном и контентом.

### React Bits — правила использования

- Источник готовых эффектных фонов и компонентов-основ. Код открытый — **правим исходники напрямую**, не ограничиваемся их пропсами. Можно брать из компонента отдельный приём/эффект, а не компонент целиком.
- ~~**Один главный WebGL-эффект на страницу**~~ — **отменено 05.08.2026**: ограничение снято, WebGL можно использовать в любом количестве секций. Взамен действует не количественное, а смысловое правило: **все шейдеры лендинга — состояния одного светового движка**, а не набор разных эффектов. Общая машинерия (дисперсия по каналам, холодный спад, домен-варп fbm, тональная компрессия) уже отработана в `Strands` и `coreShader` — новые секции строятся из неё, иначе получится стилистический винегрет, ради защиты от которого и вводился прежний лимит. Технические обязательства при нескольких канвасах: ленивый монтаж по IntersectionObserver, пауза рендера вне вьюпорта, статичный fallback при `prefers-reduced-motion`.
- Не тащим много разных компонентов (стилистический винегрет), всё перекрашиваем в наши токены.
- **Исходники для лендинга лежат в `refs/`** (положены 05.08.2026, вне сборки). Что из них берём:
  | Исходник | Что берём |
  | --- | --- |
  | `LogoLoop.tsx` | Тикер — почти как есть: rAF + модуло по ширине последовательности, число копий из ширины контейнера, `ResizeObserver`, `prefers-reduced-motion`. Выкидываем логотипы/img-загрузчик, кормим текстом. |
  | `DecryptedText.tsx` | Механику `revealedIndices` + шифрующий проход (`triggerReverse`) — для слова-подписи в Bypass и как reduced-motion-слой Privacy. **Переписываем на refs/CSS:** оригинал держит стейт на каждый символ и перерисовывает все спаны каждые 50 мс. |
  | `LightRays.tsx` | Параметризацию «якорь + направление» и угловой конус `pow(max(cosAngle,0), 1/spread)` — момент прорыва света сквозь решётку DPI в Bypass. |
  | `SideRays.tsx` | Обратностепенной спад `intensity/pow(dist, falloff)` — тот же приём, что в ядре кнопки; подтверждение калибровки. |
  | `Dither.tsx` | Только 8×8 Bayer + квантование (≈15 строк GLSL) — фактура dot-matrix карты. Сам компонент не берём: он на three.js + `postprocessing`, а у нас ogl. |
  | `ScrollReveal.tsx`, `ScrollTrigger.tsx` (это ScrollFloat) | Рецепты значений: пословная подсветка `opacity .1→1` + `blur 4→0`, `stagger .05`, scrub; у ScrollFloat — посимвольный въезд с анизотропным масштабом (`scaleY 2.3 / scaleX .7`). Сам GSAP не тащим (см. ниже). |
  | `ScrambledText.tsx` | Идею «радиус вокруг курсора, длительность ∝ расстоянию». Требует GSAP SplitText + ScrambleTextPlugin — повторяем на motion. |
  | `Stands.tsx`, `ColorBends.tsx` | Оригиналы уже портированного. |
- **GSAP не подключаем** (решение 05.08.2026): половина исходников в `refs/` написана на нём, но его козыри нам не нужны — `pin` закрывается нативным `position: sticky`, `scrub` — `useScroll`/`useTransform` из motion, а `scrollerProxy` был костылём под Locomotive v4 с transform-контейнером (у нас v5 на нативном скролле). Второй раннер анимаций и ~40 КБ ради одной секции — плохая сделка. Побочно: в `ScrollReveal.tsx` cleanup делает `ScrollTrigger.getAll().forEach(kill)`, то есть убивает и чужие триггеры на странице — при переносе рецептов этот код не копировать.

## 4. Структура лендинга

Стартовый состав (будет дополняться):

0. **Header** (реализован 31.07.2026) — fixed, полностью прозрачный: подложки и бордера нет, фон — только GradualBlur (React Bits, от исходника осталось лишь ядро приёма — стопка слоёв с backdrop-filter и градиентными масками; вся формула переписана. Маска слоя — ступень «включился и держится до кромки», а не полоса: у полосы есть конец, на котором блюр проседает до подхвата следующей, — это читалось линиями. Разгон альфы — smoothstep, а не линейный: у линейной рампы на каждом стопе излом, глаз ловит его как границу. Сила слоёв — из целевого профиля σ(t) = maxBlur·t², а не удвоением: при удвоении весь видимый переход ужимался в верхнюю четверть зоны и кромка зоны читалась как граница. 8 слоёв, на кромке суммарно 1.75rem ≈ 28px — крупный текст под хедером нечитаем, как и задумано). Зона блюра (7rem) выше навигационной строки (4rem) — контент растворяется постепенно. Сетка `[1fr_auto_1fr]`: слева Wordmark, в оптическом центре ссылки Features/Pricing/FAQ (плавный скролл к якорям секций), справа гостю — Log in (secondary, новый размер `sm` у Button), вошедшему — стеклянная пилюля «аватар-буква + ник» → /dashboard (мок-сессия `src/lib/session.ts`). Мобильный: ссылки и вход уезжают в бургер / fullscreen overlay-меню (стекло `bg-black/70 + backdrop-blur`, scroll-lock, Escape, стаггер ссылок). Появление хедера — fade сверху вслед за hero-стаггером; reduced-motion учтён.

### Наполнение секций — принятые решения (05.08.2026)

Обсуждение состава контентных секций. Принято на текущий момент:

- **Пять смысловых пунктов неоднородны и не должны стать пятью равными карточками.** Обход блокировок, приватность и гейминг — это **сценарии** («зачем»), сеть серверов и протоколы — **доказательства** («почему работает»). Протоколы вдобавок причинно объясняют обход, поэтому идут сразу за ним как его доказательство, а не отдельной равнозначной фичей.
- **Сеть — «40+ locations»**: мок в `src/data/mock.ts` (сейчас 14 серверов / 11 стран) расширяем позже под эту цифру, чтобы лендинг и dashboard не расходились.
- **Реальные названия протоколов называем** (VLESS, Reality, XTLS-Vision, Hysteria2, TUIC, WireGuard) — для основной аудитории это главный маркер достоверности.
- **Секция «How it works» отброшена**: инструкция по подключению живёт в dashboard (Setup), дублировать её на лендинге не нужно.
- Клише VPN-индустрии, которые не используем: глобус со светящимися дугами, щит с замком, «military-grade encryption», карта с пинами-каплями, фейковые логотипы изданий/аудиторов и счётчики «trusted by N million».
- **Ритм секций — чередование «свет / прибор»**: WebGL (~~Bypass~~ — графика снята 07.08.2026, см. ниже; Privacy, карта в Network) чередуется с фактурой измерительного прибора на SVG и Geist Mono (Protocols, Gaming). Пять световых секций подряд слипаются в один скринсейвер, и обход блокировок перестаёт отличаться от гейминга. По той же причине разной должна быть **механика**: Bypass ведётся скроллом (sticky), Gaming — интерактивный тумблер `Without VPN / With SpatiumVPN` (единственный на лендинге, `PillTabs`; это сравнение, а не кнопка Connect), остальные — reveal при входе в вьюпорт.
- **Порядок контентных секций:** Bypass → Protocols → Privacy → Gaming → Network → тикер → Pricing → FAQ → CTA.
- **Тикер** (приём Rig): узкая моно-полоса перед Pricing — `40+ LOCATIONS · NO LOGS · UNLIMITED BANDWIDTH · 5 DEVICES · VLESS + REALITY · WIREGUARD`. Заменяет ряд крупных цифр: подкрепить большие числа нам всё равно нечем, кроме мока.
- **Слово-подпись в заголовке Bypass** (приём Interfere, где `breaks` набрано ломающимся курсивом): слово `unfiltered` сначала набрано мусорными глифами и разбирается ровно в момент, когда поток проходит преграду. Пробуем, отношение к приёму скептическое — если на реализации не сработает, снимаем.

**Таб-бар — плавающая стеклянная пилюля** (03.08.2026), полосы во всю ширину нет, контент уезжает под неё. Подложка активной вкладки переезжает той же механикой, что в `PillTabs` (`layoutId` + spring 450/38) — движение обязано совпадать с остальными переключателями. Сам `PillTabs` не переиспользован: в нём нет disabled-опций, метки стоят в строку, а контейнер жёстко залит `bg-surface-2`, который в стеклянной панели пришлось бы перебивать конфликтующей утилитой того же веса. Под пилюлей — градиентная подложка: сплошная полоса раньше перекрывала список сама, а плавающая пилюля этого не делает, и в состоянии «выглядывает» шторка уходит ниже экрана — строки торчали из-под пилюли, срезанные нижним краем. Гасим именно градиентом, не панелью: у панели есть верхняя кромка и она читается линией.

**Кнопка — вариант «Ядро»** (выбран из трёх: «Ядро» / «Призма» / «Диафрагма»; призма отброшена как чужая стилистика и риск радуги, диафрагма взята вторичным слоем). Три слоя снизу вверх:

1. **Световое ядро на шейдере** (`coreShader.ts` + `ConnectCore.tsx`) — единственный WebGL-эффект страницы, на **ogl** (three.js не нужен: это один фрагментный шейдер на полноэкранном треугольнике). Холод берётся не подмешиванием синего, а **дисперсией**: три канала считаются на слегка разных радиусах, красный гаснет раньше синего — белое ядро с холодным спадом. Плюс домен-варп fbm-шумом, дыхание, ударная волна на нажатие (850 мс — на прежних 1100 кольцо доходило до края уже после того, как отработала кнопка, и читалось отдельным событием, а не откликом).

**Свечение подтянуто к волне** (03.08.2026). После пересборки волны свет ядра стал заметно менее достоверным: он собирался линейным сложением экспоненциальных градиентов, а фронт волны — на обратноквадратичном профиле с тональной компрессией. Перенесены оба приёма:

- **Тело ядра на `1/r³`** вместо `exp(-(r/R)^1.5·2.2)`. Прежняя экспонента на `r = 2R` даёт 0.002 — собственный свет ядра умирал сразу за диском, а всё дальше несли отдельно подмешанные ореол, beam и засветка; отсюда и ощущение стопки градиентов вместо одного источника. Степень 3, а не 2 как у волны: на `1/r²` хвост в средней зоне (`r = 1…2`) заливает весь кадр молоком и убивает контраст. Куб в этой зоне примерно повторяет прежнюю экспоненту, но дальше не обрывается.
- **Тональная компрессия** `1 - exp(-col·1.35)` в конце сборки. Раньше сумма в центре уходила далеко за единицу и срезалась клампом в плоское белое пятно с жёсткой кромкой, а переход в ореол был линейным — глаз читает такое как градиент, а не как пересвет. Усиление 1.35 не декоративное: на 1.0 кривая ощутимо подбирает нижний диапазон, а выключенное ядро целиком в нём и живёт. Ставится после множителя состояния — тусклое ядро это меньше света на входе, и компрессия обязана это видеть.
- Раскалённый центр поднят с 1.15 до 1.35 подключённым: компрессия больше не срезает пик клампом, она к нему плавно подходит, и на старом значении центр не доходил до белого. Амплитуда тела при этом обязана остаться **постоянной** (0.166 = 1/glow(0)) — попытка сделать её зависящей от `uOn` уронила выключенное состояние вдвое.

**Ореол — линза, а не круг** (03.08.2026). Дальний свет анизотропен: вбок уходит примерно в 1.7 раза дальше, чем вверх-вниз (`aniso`, коэффициент домножает уже готовые радиусы слоёв, поэтому весь накопленный домен-варп сохраняется). Ровный круг вокруг кнопки читается нарисованным ореолом; вытянутая по горизонтали форма — тем, что бывает с ярким источником в оптике, и совпадает по оси с анаморфным бликом.

Два условия, без которых форма не появляется вообще:

- **Канвас шире экрана** (`CANVAS_OVERHANG` в `ConnectButton.tsx`, 520×642 против прежних 402×402). Пока канвас упирался в ширину экрана, его собственное гашение кромок срезало свет прямо в кадре — вокруг кнопки был мягкий круг, и форма свечения не имела значения. Теперь кромка гасится вне видимой области, а по бокам свет просто уходит за край экрана.
- **Гашение кромок отодвинуто** с 0.45 к 0.75. На 0.45 маска душила свет уже на кромке диска: размер и форму ореола задавала она, а не спад света.

Когда маску отодвинули, выяснилось, сколько дальние слои светят на самом деле — весь кадр заливало ровным серым, и радиусы пришлось **ужать**: ореол с `radius·2.4` до `radius·1.4`, засветка с 2.6 до 2.2 и втрое по амплитуде. Это не «стало меньше света»: прежние числа никогда не работали целиком, их обрезала маска. Контрольные точки подключённого состояния (доля от 255, замер по скриншоту): по горизонтали 1.5 → 73, 2.0 → 54; по вертикали 1.5 → 36, 2.0 → 17; угол 2×2 → 4.

**Ударная волна пересобрана** (03.08.2026). Была гауссовым кольцом постоянной толщины на линейном радиусе — читалась бледной размытой линией, а не световым фронтом. Разобрано по причинам:

- **Энергия уходила туда, где волну не видно.** Всё до r = 1 (единица длины — радиус диска) закрыто матовым стеклом кнопки с `backdrop-blur`, а гашение кромок начинает давить с r ≈ 0.98 — полосы, где кольцо уже вышло из-под стекла и ещё не задавлено, не существовало вовсе. Поэтому **волна вынесена из-под маски кромок** и складывается после неё. Правило кромок не нарушено: маска нужна свету, уходящему в бесконечность, а волна ограничена сама — радиус доходит только до 1.9 при полуширине канваса 2.18 и гаснет раньше края, обрываться прямой линией ей нечем.
- **Радиус с сильным замедлением** (`pow(uWave, 0.45)`) вместо линейного: линейное движение читается как анимация, а не как выброс, и кольцо теперь выскакивает из-под стекла к 24% прогресса вместо 37%.
- **Огибающая яркости** — разгон по радиусу, смерть по прогрессу: пик встаёт сразу за кромкой диска, а не под ним, как раньше.
- **Профиль фронта:** асимметричный (снаружи спад в 2.5 раза круче — появляется направление движения), толщина растёт с радиусом, сердечник обратноквадратичный вместо экспоненты — приём из `Strands` (`g = w/(d + 0.45w)`, в квадрате). Гаусс при этой ширине и давал «размытую линию».
- **Тональная компрессия** `1 - exp(-x)`, тоже из `Strands`: без неё сумма упирается в кламп альфы уже серой и фронт никогда не выбивает в белое.
- **Дисперсия вместо покраски.** Была залита `mix(uIce, white, 0.55)` — то есть именно покрашена, ровно то, что правило «цвет живёт в свете» запрещает. Теперь каналы расходятся двумя способами сразу: синий идёт чуть впереди фронта и по более широкому профилю, красный отстаёт и режется уже — холодный передний край, тёплый шлейф, белое на пике. Расхождение растёт с радиусом. **Параметры критичны:** на `lead = 0.018·wr` и ширинах 0.86/1.0/1.18 каналы разъезжаются в буквальную радугу — ровно тот риск, из-за которого был отвергнут вариант кнопки «Призма». Рабочие значения втрое меньше: `lead = 0.004·wr`, ширины 0.94/1.0/1.08.
- **Слом идеальной окружности** угловым шумом от центра кнопки (шум по окружности — шва на девять часов нет). Волна была единственным объектом кадра, идущим ровным циркульным кругом, — это и выдавало в ней нарисованность. Амплитуда тоже критична: на `0.45` вместо `0.1` и частоте 2.2 вместо 1.15 получается лохматая амёба, а не оболочка.
- **Отдача ядра:** на первых ~15% волны (≈130 мс) ядро сжимается на 16% и вспыхивает в центре под матовым стеклом. Без этого волна читается отдельным слоем поверх картинки — её как будто подрисовали, а не выбросило ядро.
- **Размытие фронта на последней трети** (`dissolve`, 03.08.2026). Волна не исчезает, оставаясь до конца тем же чётким кольцом, — это читалось как «выключили слой». К концу фронт расплывается: толщина растёт ещё втрое, крутизна спадов наружу и внутрь сводится почти в равные (фронт перестаёт «лететь»). Спад яркости пришлось смягчить с 1.7 до 1.4: на более крутом волна гасла раньше, чем успевала размыться. Дальность снижена с 1.9 до 1.8 — разбухшему к концу фронту нужен запас до края канваса, иначе он обрывается прямой линией.

  **Именно размытие, а не распад.** Пробовали дополнительно рвать кольцо к концу: частый угловой шум с разрывами и сгустками плюс разгон слома окружности со второй октавой. Эффектно, но отвергнуто — волна начинает выглядеть самостоятельной анимацией, наложенной поверх экрана, а не откликом кнопки; контур при этом превращался в шевелящуюся шестерёнку. Слом окружности остаётся, но с постоянной малой амплитудой на всю жизнь волны.

   **Оптический слой (03.08.2026)** — «как будто фонариком светят на камеру». Источник смещён от геометрического центра кнопки и медленно дрейфует: артефакты объектива строятся относительно оптической оси, и при источнике ровно в центре они вырождаются в концентрические кольца, то есть в обычный радиальный градиент. Дальше — паразитная засветка (veiling glare) со степенным, а не гауссовым спадом (длинный хвост, свет доходит до краёв кадра) и двумя угловыми модуляциями: крупные медленно перетекающие «языки» модулируют РАДИУС засветки (у такого пологого хвоста модуляция яркости незаметна — проверено) и снимают ощущение ровной окружности, мелкий шум даёт нерегулярные лучи от микродефектов стекла. Анаморфный блик — намеренно на пределе различимости, по решению пользователя. Единица длины шейдера — радиус матового диска (`uUnit`), канвас квадратный и шире кнопки: свету нужен запас, иначе маска кромок гасит его сверху и снизу сильнее, чем по бокам.

   **Отброшено (03.08.2026):** кольцо из нитей Strands, свёрнутых в полярные координаты (`r = R + w(θ)` вместо `y = w(x)`). Технически работало, но нити читались блёклыми полупрозрачными линиями и на Hero похожи не были — идея закрыта, развиваем сам световой эффект.
2. **Кольцо-диафрагма** — несёт состояние: бегущая дуга на переходах (0.7 с), медленный обход подключённым.
3. **Матовый диск** поверх света: `backdrop-blur` размывает ядро под собой, поэтому свет читается сквозь стекло. Текста внутри нет — состояние проговаривают свет и блок статуса; глиф Power отделён от выбитого в белое центра тёмным ореолом.

**Калибровочные грабли (не наступать заново):**

- Цвет в шейдере — уже готовый премультиплицированный вклад света, домножать его на альфу (как делают фоны, где `col` — цвет, а `a` — покрытие) **нельзя**: спад гаснет квадратично и весь ореол за кромкой диска уходит в чёрный.
- Ядро должно быть **шире диска**, иначе весь свет остаётся под стеклом и кнопка читается как металлический шар.
- Гашение кромок канваса (правило кромок) — маской **эллиптической**, по форме канваса. У квадратной (`max` по осям) спад повторяет прямоугольник и вокруг кнопки виден светлый прямоугольник с мягкими углами.
- Ударная волна складывается **после** множителя состояния: это событие, а не состояние, иначе вспышка от нажатия гаснет ровно там, где должна быть ярче всего.
- **Угловой шум обязан сэмплироваться по окружности**, то есть `fbm(vec2(cos(ang), sin(ang)) * k)`, а не `fbm(vec2(ang * k, …))`. `atan` скачет с −π на +π, и шум от самого `ang` в этой точке рвётся: на радиально-симметричном ядре разрыв незаметен, но любой слой с угловой структурой сразу показывает прямую ступеньку на девять часов.
- `strokeDasharray`, отданный motion в `animate`, motion пересчитывает по-своему и дуга рассыпается на пунктир. Длина и прозрачность дуги едут CSS-переходами на обычном `<circle>`.
- Значения, изменённые правкой шейдера, не подхватываются HMR полностью: motion продолжает вести свойство, которое уже убрали из `animate`. Перед оценкой правки — полная перезагрузка страницы.

**Форсирование состояний.** Любой кадр ставится ссылкой, без кликов: `?state=connected|connecting|off&t=41:12&server=ams-1&sheet=peek|open&tab=home|servers&live=1`. Форсированное состояние по умолчанию **заморожено** (таймер не тикает) — иначе кадр уезжает; `live=1` возвращает ход времени.

**Скриншотер** — `scripts/shoot-app.mjs` (`npm run shoot`), puppeteer-core, снимает в 3× и вставляет кадр в рамку. Область экрана в рамке не задана константами: ищется **заливкой по прозрачным пикселям от центра** (просто «все прозрачные» брать нельзя — фон вокруг корпуса тоже прозрачный), маска берётся из инвертированной альфы, поэтому сглаженные скругления углов сохраняются, а скрипт переживёт замену рамки.
